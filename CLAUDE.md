# Agent Race Control

Minimal Electron + Svelte terminal cockpit for coding agents on native Windows — **Windows first, macOS in progress** (2026-09-12; the code no longer refuses to start off Windows, nobody has run it on a Mac yet, and there is no Mac build): one window, a **timing tower** of sessions (Claude + Codex + plain Git Bash shells; named after the F1 broadcast graphic, "tower" in code), one terminal pane. **`docs/agent-race-control-kickoff.md` is the living spec** — every decision is recorded there; fold new decisions into it before implementing.

## Two non-negotiable ethos rules

1. **Minimal.** Check every feature idea against the doc's out-of-scope list (no git/PR/kanban/graphs/themes/DB). When tempted, flag it instead of building it.
2. **Full-fidelity agent CLI.** The unmodified CLI runs in a real ConPTY. Never intercept, rewrite, or steer the byte stream. If it works in Windows Terminal but not here, it's our bug. Spawn lines live in exactly one place, `src/main/cli/`. **Claude's** blessed deviations (all documented): `--session-id`/`--settings` spawn flags, `--worktree` when the user asks a repo card for a fresh worktree (Claude Code runs the git, the app never does), user-initiated `/color` and `/rename` typing (injected only at the idle prompt — never while a dialog is open). **Codex's list is shorter, not longer:** `codex` or `codex resume <id>`, nothing else — no flags of ours, no settings file, no injected typing. App-wide and agent-neutral: the Ctrl+=/−/0 zoom keys, Ctrl+wheel per-pane zoom, dev-only F12, and the dev-only `ARC_USERDATA` userData override (screenshot harness scratch profile — ignored when packaged). Reading session state out-of-band — `claude agents --json` (`agents.ts`), the codex rollout and session index (`codex.ts`), the transcripts, the terminal title, the screen buffer — is observation, not a spawn-line deviation; none of it touches the PTY.

## Commands

- `npm run dev` — `fix-pty-perms` + electron-vite dev with HMR (main/preload changes need an app restart; renderer is hot). **Every script that starts Electron runs the chmod first** (`dev`, `preview`, `screenshots`, `dist`): a fresh clone on a Mac otherwise opens blank panes with no error, measured 2026-09-12 on the first Mac run
- `npm run build` / `npm run preview` — production build / run it
- `npm run dist` — `fix-pty-perms` (chmods node-pty’s darwin `spawn-helper`, a no-op on win32) + build + NSIS installer into `dist/` (`npm run dist:dir` for the unpacked smoke-test build; `npx electron scripts/make-icon.mjs` regenerates `build/icon.ico` from the same pixel-art PNG the app scales (`src/renderer/src/assets/arc.png`))
- `npm run typecheck` — `tsc` (main/preload) + `svelte-check` (renderer)
- `npm run test` — Vitest, **unit tests for pure logic only** (nine files: transcript reducer + path encoding, the codex rollout fold + index parsing, the screen-scan classifier's per-agent rule sets, git porcelain-v2 status parsing, session-info fold, title/status/archive/zoom/preview-cache helpers, the per-platform shell choice, the login-PATH capture/merge, the agents poll's fenced shell answer). No component tests, no E2E — UI verification is running the app. Tests `vi.mock('electron')` per file; the svelte plugin in `vitest.config.ts` lets them import runes modules directly.
- `npm run test:mutation` — StrykerJS over the Vitest suite (`stryker.config.mjs`), scoped to exactly the four tested modules (`transcript.ts`, `git.ts`, `sessioninfo.ts`, `sessions.svelte.ts`). Reports test *quality*, not line coverage; `reports/mutation/mutation.html` for the drill-down. **Read the `covered` column, not `total`** — these modules deliberately mix unit-tested pure logic with app-verified I/O (file watchers, git spawn, IPC/persistence), so `total` is dragged down by intentional no-coverage plumbing. Manual/local only — not a gate (`break: null`), no CI. Stryker instruments `.svelte.ts` runes cleanly (verified: 0 errors); its vitest-runner peers `vitest >=2`.
- `npm run format` — Prettier (config locks in the existing style; `*.md` and the lockfile are ignored)
- `npm run screenshots` — build + `scripts/screenshot.mjs`: stages the doc scene in a scratch profile (`ARC_USERDATA`) and writes seven `images/arc-*-{dark,light}.png` pairs (hero, preview, worktrees, worktree-new, reopen, session-menu, settings). Real claudes, real keystrokes, and **real** status variety (the old synthetic hook POSTs are gone — the poll's floor means a dot can't be faked from outside, so rows are made genuinely busy / genuinely blocked on a permission dialog, best-effort so a build never fails on doc images); a short scripted conversation on a fresh run, reruns resume free (delete `.screenshot-profile/` to restage — required after editing the prompts)
- `trailer/` is its own npm project (never installed by the app) — `npm run render` inside it drives the Motion Canvas editor headlessly and writes `trailer/output/`. Eight beats over 55s, built on the shipped dark screenshots; the kickoff doc's Trailer section holds the design rules. Iterate at half scale / 20fps in `src/project.meta` and pull frames with `ffmpeg -ss`, not by rendering full.

## Architecture

- `src/main/` — `index.ts` (window, zoom, menus-off, IPC), `pty.ts` (node-pty spawn/registry; session types + resume + env scrubbing), `cli/` (the per-agent spawn lines — the ONE place an agent's command is built), `shell.ts` (the per-platform shell choice + `askShell`, the ONE way to ask the shell a question and trust the fenced answer), `bash.ts` (Git Bash discovery on Windows — VS Code's algorithm, never PATH-resolve bash.exe), `login-path.ts` (repairs this process's PATH at startup: launchd's four directories on macOS, a stale parent env block on Windows; union only, appended on win32 so resolution order is untouched), `status.ts` (localhost server for per-session turn-boundary hooks), `agents.ts` (polls `claude agents --json` as the green floor, claude-only), `transcript.ts` (tails a conversation JSONL into preview items; per-agent fold), `codex.ts` (rollout discovery + the codex preview fold + the session index that names a thread), `git.ts` (read-only branch/worktree facts), `sessioninfo.ts` (pull-only facts for the Session tab), `state.ts` (state JSON in userData)
- `src/preload/index.ts` — the only renderer↔main bridge (`window.arc`), keep it minimal and explicit
- `src/renderer/src/` — Svelte 5 runes: `App.svelte` (tower, cards, menus, filter, DnD, pane tabs), `Terminal.svelte` (xterm wiring), `Preview.svelte` (the Preview tab), `Info.svelte` (the Session tab), `Notes.svelte` (the Notes tab), `screen.ts` (the screen-scan status classifier — pure, per-agent rule sets), `sessions.svelte.ts` (session/folder store + persistence; `AGENTS` holds the per-agent capabilities), `theme.ts` (GitHub palettes — exact Primer hexes, don't tweak by eye)

## Gotchas that cost real time (don't relearn these)

- **node-pty ≥1.1 is Node-API with shipped prebuilds — no `@electron/rebuild`, ever.** The npm tarball can't even be gyp-rebuilt (missing winpty files). Never leave a `build/` dir inside `node_modules/node-pty` (loader prefers it over prebuilds). Packaged builds must keep `asarUnpack: node_modules/node-pty/**` (electron-builder.yml) — the prebuilds can't be loaded or spawned from inside the asar.
- **Scrub `CLAUDECODE`/`CLAUDE_CODE_*`/`CLAUDE_EFFORT`… from spawned env** (`pty.ts`). If the app is launched from inside a Claude Code session, leaked markers make spawned claudes act as nested children — which **silently disables transcript persistence** (no resume). Fidelity = fresh terminal, not launcher ancestry.
- **Status = hooks for the turn, the poll as a green floor.** Two channels, deliberately unequal. **Hooks** (`src/main/status.ts`, injected per-session via `--settings` → token-guarded localhost server, always answer `200 {}`) carry turn boundaries and are the *only* thing that paints red/amber: `UserPromptSubmit`→running, `Stop`/`StopFailure`→end of turn, `PermissionRequest`/`Notification`→waiting. `PostToolUse` is **deliberately not subscribed** — turn start/end are the only edges needed, and not subscribing deletes the out-of-order-POST race entirely. **The poll** (`src/main/agents.ts`, one `claude agents --json` per second for the whole tower, gated on a live Claude PTY, ~275ms) is only a **floor**: `idle` forces green (the self-heal hooks never had — nothing fires on an interrupt), while **`waiting` is ignored** and **`busy` is ignored unless a turn is open**. Two guards, both added 2026-08-19 after a green dot was caught on a session that had been working for 14 minutes (see the kickoff doc): (1) `idle` is **no longer trusted on a single sample while a turn is open** — the floor needs `IDLE_TICKS_TO_END_TURN` (3) consecutive idle ticks to close a turn the hooks opened, because one transient idle used to green the dot for the rest of that turn (red comes only from `UserPromptSubmit`, already spent); with no turn open one tick still greens instantly. (2) `turnOpen` (set by `UserPromptSubmit`, cleared by `Stop`/`StopFailure`/Ctrl+C//`clear`) lets **`busy` restore red on a session that is showing green** — busy alone still cannot tell an agent from a background shell, but with a turn known to be open the two channels agree and the green is the wrong one. Amber and `delegating` stay hook-owned. That asymmetry is the load-bearing fact: **measured, `busy` includes a session whose turn ENDED but which still owns a background shell** (90/90 samples over 205s on a session idle at its prompt), and shells are not "the agent is driving". The entry carries no shell or agent count to disambiguate — exactly `pid, cwd, kind, startedAt, sessionId, name, status`. Other verified facts (v2.1.229): interactive sessions **do** appear despite the docs saying otherwise (the one contract risk); the reported `sessionId` is exactly our pinned `--session-id`; matching is **pid-first, sessionId-second** since `claude.exe` is a grandchild of our PTY's bash, and the claude pid survives `/clear` (`startedAt` guards pid reuse). The poll entry also carries the current conversation id (`/clear` follow) and real `cwd` (`--worktree` adoption). Fourth state **`delegating`** (main turn over, subagents still working) = waiting's amber **without the pulse**, from counting `SubagentStart`/`SubagentStop`; a busy main agent always outranks it. Only **Ctrl+C** remains as keystroke inference (no hook fires on an interrupt, and the floor can't help while a shell holds `busy`); **Esc stays out** — its ambiguity with the `/btw` menu is issue #6. **Never write to the user's `~/.claude/settings.json`.** **Codex uses none of this** — its terminal title carries running, waiting AND blocked on its own, so it runs on the screen scan (`screen.ts`) with its own rule set: no hook server, no poll, no `--settings`. Hence the *Status detection* setting governs **Claude rows only** — it picks a technique where there is a choice.
- **Resume:** we pin `--session-id <uuid>` at spawn; on restore, `--resume` only if the transcript `~/.claude/projects/<cwd-encoded>/<uuid>.jsonl` exists, else fresh with the same id (a never-prompted session writes no transcript; resuming it errors). **Codex is the mirror image:** it has no `--session-id`, so the row spawns with no id and *discovers* it from the rollout it opens (`codex.ts` joins on cwd + `source: "cli"` + `originator: "codex-tui"` + a creation time at or after our spawn — three signals, safe against the user's own codex in another window); restore is `codex resume <id>`.
- **Transcript dir encoding dashes EVERY non-alphanumeric** in the cwd — dots, spaces, underscores (verified empirically; a `[\\/:]`-only regex silently broke preview *and* resume for dotted paths). `transcriptPath()` in `transcript.ts` is the single owner of the encoding and honors `CLAUDE_CONFIG_DIR`.
- **Version pins are load-bearing:** `@sveltejs/vite-plugin-svelte` 6.x + Vite 7 (electron-vite 5 rejects Vite 8); TypeScript 5.9 (svelte-check crashes on TS 7); Electron pinned exact.
- **Dev restarts: kill the whole `npm run dev` tree, not just `electron.exe`.** Orphaned vite/electron-vite servers accumulate and can leave the next window invisibly alive (GPU-cache contention; there's a `did-finish-load` show-fallback in main, but don't rely on it).
- **macOS runs, and is not finished (first Mac run 2026-09-12).** The four blockers are fixed (shell dispatch, the darwin `spawn-helper` chmod before *anything* that starts Electron, the startup PATH repair, the MSYS-only `cygpath`), CI typechecks + tests on both hosts, and both row types have come up in a real PTY on a Mac. Still missing: the `activate` handler, a Mac app menu (Cmd shadows nothing a TUI reads, so the zero-shadow rule allows one), a packaging target, Cmd zoom/clipboard, POSIX font stacks. Every macOS change is reviewed for its **Windows** form first — the last round introduced three Windows regressions by asserting it instead of measuring it (kickoff doc, macOS section).
- Keyboard: the app must not shadow terminal keystrokes. The default Electron menu is removed for this reason — don't reintroduce it.
